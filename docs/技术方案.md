# 拾光工坊技术方案

## 从设计参数到生产任务

系统将自然语言理解与可检查的制造数据分开。故事经本机 Kiro CLI 转为受限 JSON；程序合成多边形、检查基础结构，生成同源三维预览与 SVG。生产工作台在此基础上加入有限库存、设备工作区、数量和结构选择，最终交付板级文件、参数化底座与制作记录。

React 管理两种工作视图，Three.js 展示图案层与底座，polygon-clipping 和 Clipper 完成布尔运算及轮廓偏移，JSZip 在浏览器生成交付包。库存求解和几何处理在本机完成，不追加模型调用。

## AI 规划与基础几何

`server/plan.mjs` 限制主题、配色、天空、意象枚举和文案长度，仅接受声明式参数。四类场景、十二种意象为当前能力范围；不支持的模型输出会被拒绝。

Kiro 通过参数数组启动，无 shell 插值；运行时 Agent 的工具列表为空。故事作为不可信数据进入提示词，边界由工具禁用与独立字段校验共同落实。应用不执行模型提供的代码、命令或 SVG。

`geometry.js` 在 200 × 200 规范坐标内合成地景、意象、外框和孔洞，经过并集、差集与边界裁剪形成六层材料轮廓。检查每层连通性、有限坐标、闭合环、边界和层数，再缩放至 140 / 180 / 220 mm。同一份数据用于挤出预览、独立 SVG 和生产排版，避免展示轮廓与导出轮廓分离。

## 有限库存与结构选择

每件固定六层图案与五层间隔。整框模式为六块图案加五个整框，共 11 个零件。拼条模式用十根长条、十根短条组成五个框，共 26 个零件：长条为 S × 0.05S，短条为 0.9S × 0.05S，四条端部对接后外尺寸 S、内尺寸 0.9S。两种框的材料带面积相同，但矩形占地和装配步骤不同。

`packing.js` 将 1–6 件同款展开为唯一编号零件，读取有限库存和工作区。库存上限为八行、共四十张板；检查有限数值、合法尺寸和整数数量。板材可整体旋转适配工作区，两向都放不下的板会被排除并说明原因，不自动裁小。

排版使用确定性 MaxRects 启发式，按零件面积排序，允许 90° 旋转，并优先使用余料和已打开的板。零件之间保留完整 gap，板边只保留 margin；测试检查实际坐标不重叠、不越界和间距。未放入零件明确列入 `unplaced`，此时阻止完整生产包导出。

候选求解比较不大于当前尺寸的 140 / 180 / 220 mm 与两种结构。可行候选按成品尺寸从大到小、新板数从少到多、已用板面积从小到大排序。它选择本次启发式计算中的可行方案，不证明不存在其他排法，也不宣称全局最优。排版不利用图案孔洞、不考虑木纹或任意角度；占地率按矩形包络计算，不等于净材料利用率。

默认工作区预设为 Falcon2 400 × 415 mm、Falcon A1 305 × 381 mm，也可手动填写。预设来自官方尺寸说明，仅作为文件规划约束，不代表设备连接或认证。[Falcon 官方工作区说明](https://www.crealityfalcon.com/collections/laser-engravers)

## 细节检查、轮廓加固与试切记录

`preflight.js` 对第 2–5 层做形态学开运算：先按目标细节宽度的一半内缩，再回扩，与原轮廓比较。仅报告面积大于 0.7 mm² 的差异区域；小孔按包络短边检查。该方法用于寻找优先试切位置，可能漏掉局部风险，不是完整最小桥宽或力学分析。

加固提供 0 / 0.4 / 0.8 / 1.2 mm 档位，通过实际外扩中间层材料轮廓并裁剪到外边界实现。修改同步传到预览和导出，并重新计算风险。加固会缩小或封闭部分小孔，风险面积降低不等于强度已经验证。闭合路径、细节尺度和试切也是 Falcon 官方设计指南强调的步骤。[Falcon 分层切割指南](https://www.crealityfalcon.com/blogs/laser-academy/how-to-make-island-maps-for-laser-cutting-free)

校准片外方名义尺寸 30 mm、内孔 10 mm。输入外片实测值 O、孔实测值 H 后，估算 `k₁ = 30 − O`、`k₂ = H − 10`，取平均作为切缝估计；两者差异超过 0.15 mm 时提示复测。输入及估计随生产包保存，**不自动施加切缝补偿**。具体功率、速度和材料参数仍在设备软件中试验确认。[Falcon 材料试验说明](https://eu.crealityfalcon.com/blogs/creality-falcon-tutorial/creality-falcon-laser-series-material-settings)

## 参数化底座与生产交接

`stand.js` 生成一个连续 U 形实体，槽宽为 `11 × 实测板厚 + 总装配余量`，对应六层图案与五层间隔，不含额外外箱。板厚接受 0.8–5 mm、余量接受 0.2–2 mm。每件成品配一个底座，批量数量写入任务记录。导出二进制 STL，并检查闭合性和三角形朝向；尚未验证打印、配合与稳定性。STL 可导入 Creality Print，后续切片与打印参数由该软件处理。[Creality Print 导入说明](https://www.creality.com/help/help-creality-print-quick-start-guide)

`job-export.js` 导出每张已用板的毫米 SVG，仅包含红色 CUT 和蓝色 ENGRAVE，不将板边和界面标签当成加工路径。ZIP 同时包含：

- `parts.csv`：零件/BOM 定位表，记录成品编号、板号、坐标、占地尺寸及旋转状态。
- `job.json`：来源、方案、库存、排版、加固、细节检查、测量记录和底座参数。
- `stand.stl`、`calibration.svg`、`preview.svg`。
- `生产交接单.html`：板材核对、试切、五框拼装、层序与底座交接说明。

## 草稿、方案选择与预览性能

`draft.js` 校验本地草稿并恢复当前方案及未生成的输入，分别保留两种文本；存储失败会显示提示，不阻断编辑。不因恢复触发 Kiro 调用。手动收藏仍可保留一份备份。

生产工作台展示本次候选的缺件数和板材数，用户可以主动采用其他可行方案；选择立即同步尺寸、结构、总览与导出。修改后清除过期下载提示。总览使用与单张排版一致的 SVG 轮廓。

`render-loop.js` 合并绘制请求，插值或相机阻尼结束后停止帧循环，通过视口和页面可见性控制暂停、恢复。交互、尺寸、灯光或图层改变会重新请求绘制，卸载时释放观察器和资源。底座预览不可用时仍保留 STL 下载。

## 服务与验证

Node HTTP 服务只监听 127.0.0.1，检查来源和 JSON 类型，限制输入、输出、超时及单次并发，缓存最近十二份完全相同故事的成功方案。取消或断开会结束对应子进程并释放占用。凭据留在 Kiro CLI；作品、库存和测量记录使用浏览器本地存储。

v2.1 共 66 个测试通过，覆盖 288 组基础几何组合、字段异常、来源/缓存/并发/断开、有限库存、工作区旋转、完整间距、确定性、加固、双测量、闭合 STL、批量底座数量和交付内容。浏览器通过不足库存、结构切换、两件尺寸选择、输入异常、ZIP/STL 下载、共享方案、移动布局及材料切换时的厚度/测量状态验证。

当前为本机原型，尚无实体加工数据。暖光为视觉表达，外箱、灯具和电路另行适配；系统不生成机器 G-code，不连接或控制设备。
